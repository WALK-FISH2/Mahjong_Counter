## 2. 产品定位、名称与用途

### REQ-PROD-001 产品定位

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：产品是面向中国麻将多地区规则的纯前端胡牌番数计算器。
- 验收：
  - 核心为图形化录牌、胡牌识别、番型计算、听牌分析和规则百科。
  - 计算结果必须可解释。
  - 不包装成麻将对战游戏或博彩工具。

### REQ-PROD-002 正式名称

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：主标题为“麻将番数计算器”，副标题为“多地区规则 · 附带番表”。
- 验收：
  - 用于网页标题、PWA 名称、分享文案和关于页面。

### REQ-PROD-003 应用图标

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：应用图标采用一张原创或合法授权的像素风幺鸡麻将牌。
- 验收：
  - 用于网页图标、PWA 图标和默认分享标识。
  - 小尺寸下清晰可辨。
  - 不直接复制现成商用素材。

### REQ-PROD-004 用途声明

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：在关于或帮助中说明：本工具用于麻将规则学习、番数计算与娱乐计分，不涉及金钱、筹码兑换或博彩服务。
- 验收：
  - 不在每个页面反复展示。
  - 未来进入分数结算功能时再次可见。

### REQ-PROD-005 禁止金钱化概念

- 状态：已确认
- 适用版本：永久约束
- 需求：任何版本不得引入支付、赔付、金额、现金、筹码兑换或金钱结算概念。
- 验收：
  - 未来牌局结算只处理玩家、计分关系、分数变化和输赢分。

### REQ-PROD-006 首版发布形态

- 状态：已确认
- 适用版本：v0.1.0
- 需求：只发布响应式网页与 PWA。
- 验收：
  - 支持手机和电脑浏览器。
  - 微信内置浏览器保证核心功能。
  - 支持安装到桌面及离线使用。
  - 不开发微信小程序、Android App 或 iOS App。

### REQ-PROD-007 语言范围

- 状态：已确认
- 适用版本：v0.1.0
- 需求：只提供简体中文界面，代码结构为未来国际化留出扩展边界。
- 验收：
  - 规则百科、错误提示和复制结果统一使用简体中文。
  - 计算引擎不得硬编码 UI 文案。
  - 地方术语可登记常见别名。

## 3. 版本路线与发布

### REQ-REL-001 规则版本路线

- 状态：已确认
- 适用版本：v0.1.0～v1.0.0
- 需求：按八个版本级阶段验收：v0.1.0 大众麻将通用简化版；v0.2.0 河北推倒胡；v0.3.0 无锡麻将；v0.4.0 四川麻将；v0.5.0 国标麻将；v0.6.0 广东鸡平胡；v0.7.0 广东推倒胡；v1.0.0 全规则统一验收。
- 验收：
  - v0.2.0 包含河北通用预设和石家庄常见版。
  - v0.3.0 包含无锡本地常见版和无锡通用简化版。
  - v0.4.0 包含成都血战到底和四川血战通用版。
  - 每个版本完成后都应独立可用。

### REQ-REL-002 v0.1.0 通用能力

- 状态：已确认
- 适用版本：v0.1.0
- 需求：除大众麻将规则外，v0.1.0 必须完成计算器通用框架。
- 验收：
  - 图形化录牌、胡牌识别、听牌与弃牌分析。
  - 多拆分求最高结果及并列最高切换。
  - 临时规则调整、允许范围内的番型调整。
  - 已保存牌例、草稿、分享、复制、导入导出。
  - 规则百科、番表、响应式布局、PWA、离线与版本兼容。

### REQ-REL-003 v2.0.0 定位

- 状态：已确认
- 适用版本：v2.0.0
- 需求：v1.0.0 完成番数计算器后，v2.0.0 才独立规划牌局分数结算。
- 验收：
  - 只处理玩家、胡牌顺序、计分关系和输赢分。
  - 不涉及金额、支付、赔付或筹码兑换。
  - 与计算器共享规则引擎，但页面和数据模型相对独立。

### REQ-REL-004 预发布流程

- 状态：已确认
- 适用版本：v0.1.0 及后续大版本
- 需求：正式发布前采用 alpha 内部验证 → beta 公开测试 → rc 候选发布 → 正式版。
- 验收：
  - 使用 v0.1.0-alpha.x、v0.1.0-beta.x、v0.1.0-rc.x、v0.1.0。
  - 预发布数据记录应用、规则和计算引擎版本。
  - 页面持续标注测试版本状态。

### REQ-REL-005 正式版阻断条件

- 状态：已确认
- 适用版本：所有正式发布
- 需求：严重错算、漏算、合法性误判、数据丢失、核心流程故障属于正式发布阻断项。
- 验收：
  - 支持范围内规则测试必须全部通过。
  - 保存、恢复、导入、分享和迁移必须通过。
  - 手机、桌面和微信浏览器核心流程必须通过。
  - 轻微 UI 问题可登记已知问题后发布。

### REQ-REL-006 测试数据迁移

- 状态：已确认
- 适用版本：beta → rc → 正式版
- 需求：测试版数据升级时优先兼容迁移，并在升级前自动生成本地安全备份。
- 验收：
  - 无法可靠迁移的数据保留只读并说明原因。
  - 不得静默删除牌例、草稿或其他用户数据。

### REQ-REL-007 v0.1.0 需求冻结

- 状态：已确认
- 适用版本：v0.1.0
- 需求：当前已确认内容作为 v0.1.0 需求基线。
- 验收：
  - 规则错误和必要缺陷必须修复。
  - 新功能默认进入候选需求或远期规划。
  - 确需加入时记录变更原因、影响范围和新增任务。

## 4. 主导航与页面结构

### REQ-NAV-001 默认入口

- 状态：已确认
- 适用版本：v0.1.0
- 需求：打开应用后直接进入计算器的图形化录牌页面。
- 验收：
  - 不设置独立首次规则选择页。
  - 首次默认大众麻将·通用简化版。
  - 后续恢复上次使用规则。
  - 顶部始终提供选择规则按钮。

### REQ-NAV-002 首次规则提示

- 状态：已确认
- 适用版本：v0.1.0
- 需求：首次使用显示一次轻提示：当前使用大众麻将规则，可点击顶部切换地区规则。
- 验收：
  - 可关闭，不频繁重复，可在帮助中重新查看。

### REQ-NAV-003 移动端底部导航

- 状态：已确认
- 适用版本：v0.1.0
- 需求：移动端底部固定四个主入口：算番、规则百科、已保存牌例、设置。
- 验收：
  - 导航固定在视口底部。
  - 上方主体独立滚动。
  - 预留全面屏安全区和内容底部间距。

### REQ-NAV-004 桌面端导航

- 状态：已确认
- 适用版本：v0.1.0
- 需求：桌面端使用相同四个入口，可采用侧边栏或顶部导航。
- 验收：
  - 页面名称和信息架构与移动端一致。

### REQ-NAV-005 快速算番入口

- 状态：已确认
- 适用版本：v0.1.0
- 需求：快速算番是计算器页内的次级入口，不占用主导航。
- 验收：
  - 主要入口始终是图形化牌面计算器。

### REQ-NAV-006 页面范围

- 状态：已确认
- 适用版本：v0.1.0
- 需求：正式主页面只有计算器、规则百科、已保存牌例和设置。
- 验收：
  - 分享、导入、规则详情和番型详情作为子页面或弹窗。

### REQ-NAV-007 计算器单页滚动

- 状态：已确认
- 适用版本：移动端 v0.1.0
- 需求：计算器内部采用单页纵向滚动，顺序为选牌器 → 已录入牌面 → 和牌条件 → 分析结果。
- 验收：
  - 查看结果可平滑滚动到结果区域。
  - 不使用牌面、条件、结果分区切换。

### REQ-NAV-008 精简吸顶栏

- 状态：已确认
- 适用版本：移动端 v0.1.0
- 需求：顶部使用精简吸顶栏，持续显示当前规则及切换入口。
- 验收：
  - 必要时显示测试版和临时规则调整标识。
  - 向下滚动时可缩小高度。

### REQ-NAV-009 悬浮操作条

- 状态：已确认
- 适用版本：移动端 v0.1.0
- 需求：在固定底部导航上方显示状态相关悬浮操作条。
- 验收：
  - 牌数不足显示结构张数进度。
  - 可分析显示开始分析。
  - 计算完成显示查看结果。
  - 分析中显示状态和取消按钮。
  - 不得遮挡主体内容。

### REQ-NAV-010 页面状态保留

- 状态：已确认
- 适用版本：v0.1.0
- 需求：切换到规则百科、已保存牌例或设置时保留当前计算状态。
- 验收：
  - 返回计算器恢复牌面、结果和滚动位置。
  - 只有会替换当前牌面的操作才提示确认。

### REQ-NAV-011 返回键行为

- 状态：已确认
- 适用版本：v0.1.0
- 需求：浏览器或系统返回键优先处理应用内上一层。
- 验收：
  - 弹窗先关闭，详情返回列表。
  - 主页面间返回保留滚动位置。
  - 计算器主页面再返回才离开应用。
  - 不得清空草稿。

## 5. 视觉、主题与交互风格

### REQ-UI-001 视觉定位

- 状态：已确认
- 适用版本：v0.1.0
- 需求：界面采用现代简洁工具感加轻像素风，约 70% 工具清晰度、30% 像素特色。
- 验收：
  - 像素风用于图标、标签、提示三角、规则卡片和少量装饰。
  - 规则正文、设置和复杂说明保持现代高可读性。

### REQ-UI-002 麻将牌清晰度优先

- 状态：已确认
- 适用版本：v0.1.0
- 需求：麻将牌识别清晰度优先于像素风一致性。
- 验收：
  - 牌面只显示图形，不额外叠文字标签。
  - 若纯像素牌不清晰，可使用传统清晰或轻像素化牌面。

### REQ-UI-003 牌图版权

- 状态：已确认
- 适用版本：全生命周期
- 需求：只使用原创或明确可商用、可修改授权的麻将牌图。
- 验收：
  - 保存素材来源、作者、许可证和修改记录。
  - 可参考交互，不复制其他应用牌图、图标或完整界面。

### REQ-UI-004 主题模式

- 状态：已确认
- 适用版本：v0.1.0
- 需求：提供跟随系统、浅色、深色三种模式。
- 验收：
  - 本地记忆用户选择。
  - 深色模式不使用过暗纯黑。
  - 使用舒适的深蓝灰、墨绿等底色。
  - 麻将牌保持明亮清晰。

### REQ-UI-005 动画

- 状态：已确认
- 适用版本：v0.1.0
- 需求：使用克制的轻动画并支持减少动态效果。
- 验收：
  - 选牌、删除、切换和结果出现可有短暂反馈。
  - 禁止持续闪烁和大幅移动。
  - 跟随系统减少动态效果。
  - 设置中可手动关闭非必要动画。

### REQ-UI-006 首次引导

- 状态：已确认
- 适用版本：v0.1.0
- 需求：首次进入计算页提供一次性轻量引导。
- 验收：
  - 提示选择录入区域。
  - 提示胡牌张单独录入。
  - 提示录入完成后开始分析。
  - 可跳过并可从帮助重新查看。

## 6. 规则选择、状态与来源

### REQ-RULE-001 规则选择组织

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：规则选择按地区或规则类别分组。
- 验收：
  - 支持搜索名称和别名。
  - 最近使用置顶。
  - 显示测试版和已完整支持状态。
  - 默认预设带推荐标识。

### REQ-RULE-002 开发中规则

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：开发中规则不进入可选择列表，只在规则百科和路线图展示。
- 验收：
  - 达到测试版后才可用于计算。

### REQ-RULE-003 测试版规则

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：测试版规则可正常计算、保存、复制和分享。
- 验收：
  - 首次使用需确认。
  - 结果、牌例、复制和分享持续标注测试版和具体版本。
  - 不得伪装成已完整支持。

### REQ-RULE-004 测试版升级确认

- 状态：已确认
- 适用版本：v0.1.0 起
- 需求：测试版新版本若可能改变计算结果，需要针对该版本重新确认。
- 验收：
  - 纯文案、界面或性能修复不重复确认。

### REQ-RULE-005 已完整支持标准

- 状态：已确认

## 23. 需求变更记录

> 正文只保留当前有效结论；本节记录被推翻或调整的旧结论。

### CHG-001 自动历史改为手动保存

- 原结论：正式结果自动进入最近记录，同一会话更新一条。
- 新结论：只有用户主动点击“保存牌例”才创建记录。
- 原因：避免历史杂乱，保持用户主动控制。
- 影响：取消最近记录自动保存和数量上限设计，页面统一为“已保存牌例”。

### CHG-002 取消收藏

- 原结论：已保存牌例可收藏并在“我的收藏”筛选。
- 新结论：不做收藏，只保留保存。
- 原因：收藏和保存重复，简化界面与数据。
- 影响：删除星标、收藏筛选和 favorite 字段。

### CHG-003 保存表单精简

- 原结论：名称、备注、收藏、保存时间、最后修改时间。
- 新结论：用户只填写名称，系统维护最后修改时间。
- 原因：减少表单复杂度。

### CHG-004 名称唯一改为允许重名

- 原结论：牌例名称必须唯一。
- 新结论：允许重名，以内部唯一 ID 区分。
- 原因：常见番型名称天然容易重复。
- 影响：同名只提示，不阻止保存，不默认覆盖。

### CHG-005 取消桌面文本输入

- 原结论：桌面支持 `123m 456p` 等紧凑文本录入。
- 新结论：手机和桌面统一图形化录牌。
- 原因：使用率低、解析维护成本高。

### CHG-006 取消结果图片

- 原结论：生成简洁版和详细版结果图片。
- 新结论：不生成图片，用户自行截图。
- 原因：降低视觉适配和导出复杂度。

### CHG-007 人工补充番型延期

- 原结论：用户可手动增加系统未识别番型。
- 新结论：v0.1.0～v1.0.0 不允许人工新增番型。
- 原因：验证、冲突和测试复杂度高。

### CHG-008 自定义规则延期

- 原结论：v0.1.0 支持基于预设创建自定义规则副本。
- 新结论：v2.0.0 前不要求开发，不承诺具体版本。
- 原因：先保证既定规则准确。
- 影响：当前只保留“调整本次计算”。

### CHG-009 取消首次规则选择页

- 原结论：首次打开先选择规则。
- 新结论：直接进入计算器，默认大众麻将，顶部切换规则。
- 原因：减少首次使用步骤。

### CHG-010 和牌方式默认值调整

- 原结论：自摸/点炮默认不选择。
- 新结论：默认点炮，自摸作为单选切换。
- 原因：减少一步操作；圈风和门风仍不默认。

### CHG-011 移动端分区切换改为单页滚动

- 原结论：牌面、条件、结果分区切换。
- 新结论：单页纵向排列。
- 原因：便于同时核对和回改。
- 影响：增加吸顶栏、固定底部导航和悬浮操作条。

### CHG-012 选牌器底部面板改为上方直接展示

- 原结论：移动端使用底部可展开选牌器。
- 新结论：默认在页面靠上一次展示全部 34～42 种牌。
- 原因：实际只有四至五行，展开面板增加操作步骤。
- 影响：底部面板仅保留为空间不足时的降级预案。
