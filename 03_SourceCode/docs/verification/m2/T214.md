## 2. Canonical Fixture

输入对象故意使用非 canonical 键顺序：

```json
{"b":2,"a":1}
```

canonical payload：

```json
{"a":1,"b":2}
```

规则：对象键按稳定字典序输出；数组顺序保留；只接受已验证的 JSON 数据值；循环引用和非有限数值不进入 canonical payload。

## 3. 稳定 Hash

- 算法：SHA-256，通过 `crypto.subtle.digest` 计算。
- Manifest 表达：64 位小写十六进制摘要。
- 上述 canonical fixture 的稳定摘要：

```text
43258cff783fe7036d8a43033f830adfc60ec037382473548ac742b888292777
```

相同数据采用不同对象键插入顺序时，canonical payload 和摘要保持相同：`PASS`。

## 4. 篡改与不可变版本检测

| 检查 | 结果 |
|---|---|
| 原 fixture 与稳定摘要匹配 | PASS |
| 将 `b` 从 `2` 改为 `3` 后与原摘要比较 | PASS：检测为 mismatch |
| 非 64 位小写 SHA-256 摘要 | PASS：Manifest / verification 拒绝 |
| 相同 `(ruleId, ruleVersion)`、相同 hash | PASS：`same-content` |
| 相同 `(ruleId, ruleVersion)`、不同 hash | PASS：`immutable-version-conflict` |
| 不同 Rule Version、不同 hash | PASS：`distinct-version` |

SHA-256 在本项目中只用于内容完整性、损坏检测和版本内容冲突检测，**不是来源签名**，不证明发布者身份或内容真实性。

## 5. RuleSource 与 SourceRef

- `RuleSource.sourceId` 继续通过严格 Schema 校验并要求同一目录内唯一。
- `Pattern.sourceRefs` 必须解析到同一 RulePackage 已声明的 `RuleSource`。
- 缺失 source reference 的外部输入被拒绝。
- Source URL 只接受 HTTP/HTTPS；规则计算不依赖实时访问外部网站。
