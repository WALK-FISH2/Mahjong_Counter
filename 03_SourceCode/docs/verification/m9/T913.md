## 1. Capability 和用户可见行为

Saved/Trash/Draft/RuleSnapshot 读取共用 Storage Capability。基础设施将真实存储异常映射为 STORAGE_UNAVAILABLE / STORAGE_QUOTA；Application 保持业务冲突、损坏记录、丢失编辑锁与存储能力故障的区别。

`persistent → temporary` 后：

| 能力 | 行为 |
| --- | --- |
| 主编辑器录牌、Domain/Engine 正式计算 | 继续可用，不将临时模式当作计算错误 |
| 百科和只读结果 | 可用；不能读取的本地记录明确报告，不伪造内容 |
| 正式保存、更新/另存 | 暂停；保存入口不出现或编辑操作禁用；Service/Repository 同时拒绝 |
| Draft 自动写入/恢复 | 暂停；清除“草稿已保存”提示，不承诺未落盘输入已保留 |
| Trash 持久写入 | Repository 拒绝，界面显示错误，不报成功 |
| Undo/Redo | 当前会话内仍可用 |
| 多标签 takeover | 使用 Web Locks 或 BroadcastChannel fallback 协调；不写入失效存储 |
| Import/Export/Backup | 本 Batch 未实现，不添加未来入口，不伪称该链路已验证 |

持续提示：“临时使用模式”“本地存储不可用或空间不足……保存牌例、草稿恢复和持久化写入已暂停。不要关闭尚未保留的输入。”

“重新检测存储”通过真实事务探测读写；保留现有 Draft 原始值。恢复能力后先显示明确的草稿选择，不能把临时会话自动覆盖回旧 Draft。

## 2. 原失败及本轮修复

- 原 E2E 失败不是存储故障未模拟成功：Temporary Mode 和计算均正常，但断言仍要求“保存牌例”按钮存在且 disabled；实际产品入口已移除。改为严格验证入口不存在，保留显式提示、完整计算成功、旧记录不变、恢复后选择等断言。
- 额外修复统一 Capability 通知：原先只有 Draft 自己捕获异常时才更新 controller；若 Saved/Trash 读取故障发生在 Draft pending 状态，恢复 UI 被隐藏后 Calculator 仍可能被 pending 锁住。controller 现在订阅统一 storage 状态，解除待恢复 UI、清除 savedAt 并让合法主编辑器继续临时计算；原持久记录不变。
- 为 IndexedDB 失效时 Web Locks 缺失的组合补充广播 lease 协调，验证旧主标签接管后只读，不靠移除保护恢复计算。

没有放宽合法性、revision 或正式保存资格；没有把错误吞掉或改成成功返回。

## 5. 限制与结论

- 故障是确定性 API/事务注入，未填满用户真实磁盘或清除用户浏览器数据。
