# 2. 产品定义

## 2.1 产品名称

- 主标题：**麻将番数计算器**
- 副标题：**多地区规则 · 附带番表**

对应：`REQ-PROD-002`

标题和副标题必须用于：

- 网页标题；
- PWA 名称；
- 默认分享标识；
- 设置中的“关于本工具”。

应用图标采用原创或合法授权的像素风幺鸡麻将牌，并同时用于 favicon、PWA 图标和默认分享标识。图标及麻将牌素材必须记录作者、来源、License 和修改情况，并通过小尺寸可读性验收。

对应：`REQ-PROD-003`、`REQ-UI-003`

## 2.2 产品定位

产品是一个面向中国麻将多地区规则的**纯前端胡牌番数计算与规则学习工具**。

核心价值：

1. 图形化录入当前手牌；
2. 判断当前牌面是否可和；
3. 识别并计算番型；
4. 枚举合法拆分并选择最高合法结果；
5. 分析听牌与“打哪张后进入听牌”；
6. 展示明确计算过程；
7. 提供各地区规则百科和番表；
8. 保存、分享和复现典型牌例。

对应：`REQ-PROD-001`、`REQ-REL-002`

## 2.3 永久产品边界

产品用于：

- 麻将规则学习；
- 番数计算；
- 娱乐计分。

产品不得提供：

- 金额结算；
- 支付；
- 赔付；
- 现金或筹码兑换；
- 赌博或下注服务。

对应：`REQ-PROD-004`、`REQ-PROD-005`

# 3. v0.1.0 范围

## 3.1 当前版本目标

`v0.1.0` 必须交付：

### 规则

- **大众麻将·通用简化版**
- 与国标麻将严格区分
- 作为首次使用默认规则

其正式规则事实固定为：

- Rule ID：`common-simple`
- Rule Version：`1.0.0`
- 牌组：144 张，包含 8 张花牌
- 结构：普通结构、七对、十三幺
- 当前不支持结构：七星不靠、全不靠、组合龙
- 番型：81 个参考番型，其中 78 个启用、3 个因当前结构能力禁用
- `minimumFan = 0`
- 自摸 `+1`
- 花牌每张 `+1`
- 默认不封顶
- 不包含庄家翻倍、房间加倍、胡后翻牌等平台奖励规则

上述事实以 `docs/rules/common-simple/rule-spec-v1.0.md` 为规范性依据；产品行为不得把该预设描述为国标麻将。

### 通用计算器能力

- 图形化牌面录入；
- 手牌、胡牌张、副露、杠、花牌表达；
- 和牌条件录入；
- 和牌结构识别；
- 多拆分枚举；
- 番型识别；
- 最高合法结果；
- 临时规则调整；
- 已识别番型人工取消/强制计入；
- 听牌分析；
- 弃牌后听牌分析；
- 规则百科；
- 保存牌例；
- 单草稿；
- 分享链接；
- 文字复制；
- JSON 导入导出；
- PWA、离线和本地数据；
- 响应式布局；
- 基础无障碍；
- 版本和迁移机制。

对应：`REQ-REL-002`

# 4. 用户与核心任务

本版本不要求建立账号体系，因此产品不区分登录身份。

统一用户可完成以下核心任务：

## UC-01 计算一副已知胡牌的番数

1. 打开应用；
2. 确认或切换规则；
3. 图形化录入牌面；
4. 单独指定胡牌张；
5. 补充点炮/自摸等上下文；
6. 开始分析；
7. 查看最高合法结果；
8. 展开完整计算过程；
9. 可保存、复制或分享。

## UC-02 分析当前听哪些牌

1. 录入结构有效的听牌前牌面；
2. 不设置胡牌张；
3. 开始分析；
4. 查看合法待胡牌；
5. 查看每张待胡牌在当前和牌方式下的最高合法结果。

## UC-03 分析完整手牌打哪张后听牌

1. 录入完整但未和的牌面；
2. 开始分析；
3. 系统标记可弃牌候选；
4. 点击候选牌；
5. 查看弃牌后的听牌列表。

## UC-04 查看规则和番表

1. 进入规则百科；
2. 搜索规则或番型；
3. 查看番型值、条件、关系、来源和示例；
4. 可将测试版/已完整支持规则的示例带入计算器。

## UC-05 保存典型牌例

1. 得到正式合法结果；
2. 点击“保存牌例”；
3. 接受默认名称或修改名称；
4. 保存后继续停留在当前结果；
5. 后续从“已保存牌例”中打开查看或编辑。

## UC-06 分享牌面

1. 在胡牌结果、不能胡分析或听牌分析中点击“分享链接”；
2. 查看分享摘要；
3. 确认复制链接；
4. 若链接超长，改用单牌例 JSON。

## 5.3 状态保持

- 当前规则；
- 牌面；

- 和牌条件；
- 计算结果；
- 临时规则调整；
- 番型人工调整；

- 新建牌面；
- 打开另一已保存牌例进行编辑；
- 打开导入内容；
- 打开分享内容。

# 6. Calculator 页面规格

## 6.1 首次进入

首次打开应用：

1. 直接进入 Calculator；
2. 默认规则为“大众麻将·通用简化版”；
3. 显示一次轻提示：

> 当前使用大众麻将规则，可点击顶部切换地区规则。

4. 显示一次轻量操作引导：
   - 先录入手牌或选择副露录入；
   - 胡牌张需要单独录入；
   - 牌面完成后开始分析。

后续进入：

- 默认恢复上次使用规则；
- 若存在草稿，按草稿恢复流程处理；
- 分享链接或导入内容的规则优先于“上次使用规则”。

对应：`REQ-NAV-001`、`REQ-NAV-002`、`REQ-UI-006`

---

## 6.2 移动端页面顺序

移动端 Calculator 采用单页纵向流程：

```text
顶部精简栏
↓
选牌器
↓
已录入牌面
↓
和牌条件
↓
分析结果
↓
底部悬浮操作条
↓
固定主导航
```

不使用“牌面 / 条件 / 结果”页签切换。

对应：`REQ-NAV-007`～`REQ-NAV-009`

## 6.3 桌面端布局

宽屏桌面：

- 左侧：
  - 规则和选牌器；
  - 手牌录入；
  - 副露/花牌录入入口；
  - 已录入牌面；
  - 胡牌张。
- 右侧：
  - 和牌条件；
  - 分析状态；
  - 结果；
  - 结果操作。

窗口宽度不足时响应式降级为单列。

左右两侧共享同一计算状态。

对应：`REQ-NAV-012`

# 7. 规则选择规格

## 7.1 顶部当前规则

Calculator 顶部必须持续可见：

- 当前规则名称；
- 当前规则状态；
- “选择规则”入口；
- 必要时的测试版标识；
- 必要时的“本次规则已调整”标识。

## 7.2 规则选择器

规则选择页面/弹窗：

- 按地区或规则家族分组；
- 支持规则名称和别名搜索；
- 最近使用规则优先；
- 默认预设可显示“推荐”；
- 只允许选择：
  - 测试版；
  - 已完整支持。
- 开发中只可在百科查看，不可用于计算。

对应：`REQ-RULE-001`～`REQ-RULE-005`

## 7.3 测试版规则

首次使用测试版：

- 显示风险说明；
- 用户确认后才能进入正式计算。

若规则版本更新且可能改变计算结果：

- 需要针对新版本再次确认。

纯文案、视觉、性能更新不要求重复确认。

对应：`REQ-RULE-003`、`REQ-RULE-004`

## 7.4 地方争议项

存在多种地区常见约定时：

- 系统预设采用资料支持较充分的常见约定；
- 争议项不堆叠到主界面；
- 允许调整的争议项进入“调整本次规则”；
- 规则详情展示默认约定、备选约定、争议说明和来源。

对应：`REQ-RULE-007`、`REQ-RULE-010`

# 8. 选牌器规格

## 8.1 展示原则

选牌器一次展示**当前规则实际使用的全部牌种**。

每种牌只出现一个可点击按钮，而不是四个物理副本。

典型范围：

- 万筒条：27 种；
- 字牌：7 种；
- 花牌：8 种；
- 27：只使用三门序数牌；
- 34：三门序数牌 + 字牌；
- 42：三门序数牌 + 字牌 + 花牌。

这些只是典型数量，实际范围由当前规则决定。

例如未来四川麻将规则不使用字牌和花牌时，只展示 27 种。

对应：`REQ-INPUT-002`

## 8.2 不适用牌类

规则不使用的牌：

- 直接隐藏；
- 不以灰色牌占位；
- 可在附近给出轻量说明。

## 8.3 数量角标

每种牌显示全局已使用数量。

“全局使用”包括：

- 暗手牌；
- 胡牌张；
- 吃；
- 碰；
- 明杠；
- 暗杠。

普通牌达到 4 张：

- 原按钮在原位置禁用；
- 显示 `×4`；
- 删除后恢复可选；
- 不发生选牌器重排。

花牌每种最大数量由规则决定，常见为 1 张。

对应：`REQ-INPUT-015`、`REQ-INPUT-016`

# 9. 牌面录入规格

## 9.1 默认录入状态

默认状态：

```text
activeInput = 手牌
```

用户直接点击选牌器时，将牌加入暗手牌。

## 9.2 固定区域

页面长期显示两个固定区域：

- **手牌**
- **胡牌张**

以下不设置长期空白录入区：

- 吃；
- 碰；
- 明杠；
- 暗杠；
- 花牌。

对应：`REQ-INPUT-004`、`REQ-INPUT-005`

## 9.3 临时录入入口

在牌面录入区提供清晰入口：

- 吃
- 碰
- 明杠
- 暗杠
- 花牌

点击后进入对应临时录入状态。

临时状态必须明显标明当前正在录入什么。

---

## 9.4 暗手牌

暗手牌：

- 按点击顺序显示；
- 相同牌分别显示，不折叠；
- 点击已录入牌删除一张；
- 删除支持撤销；
- 提供“一键整理”；
- 一键整理只改变视觉顺序；
- 不支持拖拽排序。

对应：`REQ-INPUT-006`、`REQ-INPUT-007`

---

## 9.5 吃牌

点击“吃”：

1. 出现小型临时录入界面；
2. 提供 3 个牌位；
3. 用户逐张选择；
4. 已放入临时牌位的牌可点击撤回；
5. 系统校验同花色连续。

第三张不合法：

- 拒绝该第三张；
- 保留前两张；
- 显示原因；
- 用户可继续选择合法牌。

三张合法：

- 自动形成正式吃牌组；
- 退出临时录入；
- 将完整牌组加入已录入牌面；
- 牌组明显标记“吃”；
- 恢复默认手牌录入状态。

对应：`REQ-INPUT-012`、`REQ-INPUT-014`

### 未完成吃牌退出

若吃牌尚未完成，用户尝试：

- 关闭临时录入；
- 切换到其他副露录入；
- 操作胡牌张；

必须先提示：

- 继续完成吃牌；
- 放弃本次吃牌；
- 留在当前录入流程。

临时牌不得计入正式牌面。

对应：`REQ-INPUT-013`

---

## 9.6 碰牌

点击“碰”后：

1. 临时状态提示正在录入碰牌；
2. 用户选择一种牌；
3. 系统自动生成三张；
4. 验证全局牌数；
5. 成功后形成正式牌组；
6. 标记“碰”；
7. 自动退出并恢复手牌录入。

不要求用户点击三次。

对应：`REQ-INPUT-008`

---

## 9.7 明杠与暗杠

点击“明杠”或“暗杠”后：

1. 用户选择一种牌；
2. 系统自动生成四张；
3. 验证全局牌数；
4. 完成后作为正式牌组展示；
5. 标明“明杠”或“暗杠”；
6. 恢复手牌录入。

不要求连续点击四次。

对应：`REQ-INPUT-009`

### 明杠类型

当当前规则需要区分：

- 大明杠；
- 补杠 / 加杠。

若规则不区分，不额外要求用户选择。

已有碰牌可升级为补杠。

对应：`REQ-INPUT-010`

### 暗杠展示

编辑状态：

- 四张具体牌正面可见，避免用户无法核对。

结果/复制/分享展示：

- 可以采用符合暗杠习惯的视觉；
- 详情仍可查看真实牌种。

对应：`REQ-INPUT-011`

---

## 9.8 花牌

仅当前规则支持花牌时显示“花牌”入口。

用户进入花牌临时录入后：

- 选择具体花牌；
- 系统记录春夏秋冬梅兰竹菊的真实牌种；
- 完成后退出临时录入；
- 已录入花牌在牌面区域集中展示并有明确花牌标识；
- 不占用长期固定空白录入区。

花牌：

- 不计入普通结构有效张数；
- 具体身份可参与正花、本花等规则判断。

对应：`REQ-INPUT-019`

---

## 9.9 已录入牌面布局

已录入牌面统一展示：

- 普通暗手牌；
- 已完成吃牌；
- 已完成碰牌；
- 已完成明杠；
- 已完成暗杠；
- 已录入花牌；
- 独立胡牌张。

视觉可以集中，但语义必须保持分离。

副露必须用：

- 分组；
- 边框；
- 牌组卡片；
- 文字标签；

中的一种或组合，确保用户能一眼区分。

副露不得因为视觉上放在一起而参与暗手牌重新拆分。

对应：`REQ-INPUT-005`

---

## 9.10 编辑副露

点击已完成的吃、碰、杠：

- 以整组为单位进入修改或删除；
- 不允许直接删除其中一张而形成残缺副露；
- 删除支持撤销。

对应：`REQ-INPUT-007`

---

# 10. 胡牌张规格

## 10.1 独立胡牌张

胡牌张：

- 始终单独显示；
- 最多一张；
- 不和暗手牌、副露、花牌混为同一区域。

选择新的胡牌张：

- 直接替换旧胡牌张；
- 支持撤销；
- 若导致同牌全局超过四张则拒绝。

对应：`REQ-INPUT-017`

## 10.2 完整 14 张放入手牌

若用户把完整 14 张都录入手牌，且系统发现牌面结构已经和：

- 不直接猜测胡牌张；
- 提示用户确认；
- 可推荐最后录入的一张；
- 用户必须主动指定一张移入胡牌张。

没有独立胡牌张时，不生成正式和牌结果。

对应：`REQ-INPUT-018`

# 11. 牌数与结构进度

系统同时展示：

- **结构张数**
- **实际录入张数**

例如：

```text
结构张数：13/14
实际录入：15张（含1组杠、1张花牌）
```

规则：

- 一组杠在普通结构中按一个三张面子计算；
- 第四张不增加结构张数；
- 花牌不计结构张数；
- 目标结构张数由规则配置。

当前 v0.1.0～v0.7.0 业务均为普通 14 张牌制，但实现不得把 13/14 作为不可扩展常量。

对应：`REQ-INPUT-021`、`REQ-ENGINE-005`

# 12. 待修正状态

出现以下情况时进入“待修正状态”：

- 导入数据存在不能即时自动处理的异常；
- 规则切换后用户选择保留不兼容牌；
- 其他无法在点击阶段直接阻止的非法牌面。

待修正状态必须：

- 保留用户输入；
- 标记错误位置；
- 说明原因；
- 暂停正式分析；
- 暂停保存牌例；
- 暂停生成分享链接；
- 提供定位错误、删除异常内容等操作。

用户修复后自动退出待修正状态。

普通牌第五张等可在点击阶段直接阻止的问题，不进入待修正状态。

对应：`REQ-INPUT-025`

## 13.1 默认和牌方式

提供：

```text
点炮 | 自摸
```

单选切换。

对应：`REQ-CONTEXT-001`

## 13.2 条件展示

规则相关条件采用动态展示：

- 常用条件直接显示；
- 低频条件放入“更多和牌条件”；
- 当前规则无关选项隐藏。

可能包括：

- 杠上花；
- 抢杠和；
- 海底；
- 河底；
- 门风；
- 圈风；
- 绝张；
- 其他规则声明的必要状态。

对应：`REQ-CONTEXT-002`

## 13.3 自动识别与人工提供

牌面可以确定的条件不得要求用户重复勾选。

例如：

- 门前清；
- 缺一门；
- 无字；
- 清一色；
- 七对。

牌面无法确定的条件由用户输入。

例如：

- 自摸；
- 杠上花；
- 抢杠和；

- 门风；

## 13.4 不擅自默认影响结果的信息

- 缺少时标记信息不足；
- 可展示已经确定的部分；
- 不生成正式总结果。

对应：`REQ-CONTEXT-004`、`REQ-CONTEXT-008`

## 13.5 条件兼容

- 自动移除与新模式不兼容的条件；
- 显示轻量提示；
- 支持撤销；
- 兼容条件继续保留。

特殊条件可否同时成立由规则控制：

- 可叠加 → 复选；
- 互斥 → 单选或禁用；
- 禁用时说明原因。

对应：`REQ-CONTEXT-005`～`REQ-CONTEXT-007`

# 14. 分析入口与状态

## 14.1 输入不足

当结构不足以分析：

悬浮操作条显示：

```text
结构张数 X / 目标张数
```

不显示正式结果。

## 14.2 可分析

达到当前规则定义的分析条件后：

显示主操作：

```text
开始分析
```

## 14.3 分析中

展示：

- “正在分析”状态；
- 可取消；
- 超过约 0.5 秒时必须有明显进行中反馈；
- 超过约 5 秒时提示耗时较长，并继续允许取消。

用户修改牌面、胡牌张或相关条件后：

- 当前旧分析立即失效；
- 不得继续显示旧结果为当前正式结果。

对应：`REQ-ENGINE-010`～`REQ-ENGINE-012`

## 14.4 首次结果后

首次正式分析完成后：

- 修改胡牌张；
- 修改和牌条件；
- 修改临时规则；
- 修改番型调整；

可自动重新计算。

重计算应防抖，避免连续操作触发过量分析。

# 15. 和牌结构与拆分

## 15.1 v0.1.0 支持结构

计算引擎能力必须支持：

- 四组面子 + 一对将；
- 七对；
- 十三幺。

具体某规则是否启用，由规则预设决定。

国标的全不靠、七星不靠、组合龙等在 v0.5.0 加入。

对应：`REQ-ENGINE-001`

## 15.2 多结构

同一牌面同时符合多个已启用结构：

- 全部计算；
- 不按固定结构优先级提前停止；
- 比较最终合法结果；
- 默认展示最高合法结果。

对应：`REQ-ENGINE-002`

## 15.3 多拆分

普通和牌存在多个合法拆分：

- 枚举全部；
- 每种拆分独立识别番型和计分；
- 不把不同拆分的番型拼接；
- 比较最终结果；
- 只展示最高方案；
- 并列最高时允许切换。

对应：`REQ-ENGINE-003`

## 15.4 并列最高

若多个方案最终结果相同且共同最高：

- 顶层只显示一次最终值；
- 提供方案切换；
- 结果牌面随方案切换；
- 保存牌例时保存全部并列最高方案；
- 记录用户最后查看方案。

对应：`REQ-ENGINE-004`

# 16. 分析结果类型

系统分析后可以进入以下结果类型之一。

## RESULT-A 正式合法和牌

条件：

- 结构合法；
- 当前规则允许该结构；
- 满足起胡门槛；
- 满足必须的特殊条件；
- 必要上下文完整；
- 已指定胡牌张。

可执行：

- 保存牌例；
- 复制；
- 分享；
- 查看完整过程；
- 调整本次规则；
- 番型人工调整。

另提供弱化入口：

```text
忽略当前和牌，继续分析出牌
```

该入口只启动弃牌后听牌分析，不改变当前正式和牌结果，也不得干扰主操作流程。

## RESULT-B 结构成和但当前规则不能胡

例如：

- 低于起胡门槛；
- 缺一门未满足；
- 当前规则存在其他限制。

展示：

- “结构成和，但按当前规则不能胡”；
- 明确原因；
- 不显示合法总结果；
- 不允许保存；
- 可以复制或分享；
- 可继续进行弃牌分析。

对应：`REQ-ENGINE-008`

## RESULT-C 完整牌面未和

系统：

- 分析打哪张后能立即听牌；
- 可弃牌候选在牌面上标三角。

如果无任何一步弃牌后听牌：

```text
当前尚未听牌
```

不显示向听数或多步改良分析。

对应：`REQ-ENGINE-007`

## RESULT-D 当前牌面已听

当前规则下结构达到听牌分析条件且没有胡牌张：

- 展示当前可胡牌；
- 区分合法听牌和待确认/结构可和但不合法。

对应：`REQ-ENGINE-006`、`REQ-WAIT-*`

## RESULT-E 信息不足

牌面可能可以计算，但缺少会改变结论的上下文：

- 显示当前已确定内容；
- 标记待确认项目；
- 不生成正式总结果；
- 不允许正式保存；
- 不允许生成正式分享结果。

对应：`REQ-CONTEXT-008`

## RESULT-F 计算异常

发生引擎异常：

- 保留牌面；
- 保留规则；
- 保留条件；
- 不猜测结果；
- 提供重试；
- 提供撤销最近操作；
- 提供复制问题信息；
- 当前状态继续保存为草稿。

对应：`REQ-ENGINE-013`

# 17. 正式结果页规格

## 17.1 顶层结果

最上方突出：

- 当前最高合法结果；
- 使用当前规则原生单位，例如番、台、花、倍、分。

不得强制统一单位。

对应：`REQ-RESULT-001`、`REQ-RESULT-002`

## 17.2 当前方案牌面

默认按最高拆分重新排列：

- 暗手牌；
- 吃；
- 碰；
- 明杠；
- 暗杠；
- 将牌；
- 胡牌张高亮。

提供：

```text
查看原始牌面
```

原始牌面保持用户录入顺序。

对应：`REQ-RESULT-015`

## 17.3 番型摘要

默认展示：

- 计入番型；
- 每个番型数值；
- 未计入但已识别番型；
- 未计入原因；
- 封顶前值；
- 封顶后值；
- 独立于封顶之外的项目。

## 17.4 完整计算过程

展开后至少能够查看：

- 当前结构；
- 当前拆分；
- 番型识别依据；
- 使用的牌组；
- 包含关系；
- 互斥关系；
- 不重复计分原因；
- 计算顺序；
- 起胡门槛；
- 封顶过程；
- 规则版本；
- 计算引擎版本；
- 规则资料来源；
- 并列最高方案。

对应：`REQ-RESULT-003`～`REQ-RESULT-006`

# 18. 封顶规格

有封顶的规则：

- 顶层显示最终封顶值；
- 同时显示封顶前原始合计；
- 明确显示“已封顶”；
- 完整过程显示封顶发生在哪一步。

如果某些项目按规则位于封顶之外，例如某些花牌、杠分：

- 单独展示；
- 不与封顶内项目混淆。

用户取消番型后：

- 实时重新判断是否还达到封顶。

对应：`REQ-RESULT-003`

# 19. 番型人工调整

## 19.1 允许操作

v0.1.0～v1.0.0 只允许：

### 取消计入

对系统已识别且已计入番型取消。

### 强制计入

对系统已经识别，但因为：

- 包含；
- 互斥；
- 不重复计算；

而未计入的番型进行强制计入。

对应：`REQ-RESULT-007`

## 19.2 禁止操作

不得：

- 新建系统未识别番型；
- 手动输入任意番型名称改变结果；
- 通过人工调整使原本不能胡变成正式合法胡牌。

对应：`REQ-RESULT-008`、`REQ-RESULT-009`

## 19.3 调整失效

牌面、条件变化后：

- 仍适用调整保留；
- 已不适用调整进入“失效调整”；
- 失效项不计分；
- 不自动删除；
- 用户可清除。

强制计入项重新产生冲突时，需要重新确认。

对应：`REQ-RESULT-014`

# 20. 调整本次规则

## 20.1 功能定位

“调整本次规则”不是自定义规则系统。

它只改变**当前这一次计算所采用的规则参数**。

可能开放：

- 起胡门槛；
- 封顶；
- 自摸算法；
- 常见地方争议开关；
- 已有番型启用/禁用；
- 已有番型番值。

具体开放项由当前规则声明。

对应：`REQ-RESULT-010`

## 20.2 禁止调整

不允许：

- 修改识别算法；
- 编写表达式；
- 自定义代码；
- 任意编辑规则关系图；
- 保存为长期自定义规则。

## 20.3 应用流程

进入调整页面/弹窗：

1. 修改参数；
2. 修改尚未影响当前结果；
3. 点击“应用到本次计算”；
4. 一次性重新计算；
5. 结果标记“本次规则已调整”。

直接关闭而未应用：

- 放弃未应用修改。

## 20.4 生命周期

临时调整：

- 当前草稿内恢复；
- 当前牌例保存时保留；
- 分享当前牌例时保留；
- 切换规则时清除；
- 新建牌面时清除；
- “恢复系统预设”时清除。

应用升级后若某调整不兼容：

- 不静默应用；
- 提示重新确认。

对应：`REQ-RESULT-011`

## 20.5 合法性

与番型人工调整不同：

**本次规则调整可以改变合法性。**

例如系统预设起胡 8 番，临时调整为 6 番：

- 系统预设结论仍保留；
- 当前规则结论可以变为合法；
- 允许保存；
- 保存时必须保留调整明细。

对应：`REQ-RESULT-012`

# 21. 三层结果规格

根据当前操作按需展示：

## Layer 1 系统预设结果

系统原始预设。

## Layer 2 本次规则结果

存在临时规则调整时出现。

## Layer 3 用户调整结果

存在番型人工调整时出现。

展示规则：

- 没有该类调整时不增加无意义层级；
- 有临时规则调整时，主结果为“本次规则结果”；
- 用户调整结果必须持续显示人工调整标识；
- 系统预设结果不能被覆盖；
- 复制、分享和保存应记录调整类型。

对应：`REQ-RESULT-013`

# 22. 听牌分析规格

## 22.1 当前听牌

当牌面处于可听分析状态：

- 系统考虑所有当前规则启用的和牌结构；
- 同一待胡牌只显示一次；
- 对每一待胡牌取最高合法结果；
- 并列最高可进入详情切换。

## 22.2 显示方式

使用真实麻将牌图标。

每张待胡牌上方或附近显示：

- 当前和牌方式下最高合法结果；
- 使用当前规则原生单位。

## 22.3 合法听牌

只有按当前规则真正可以正式胡牌的牌，才能进入“合法听牌”主列表。

结构可和但：

- 不达门槛；
- 不满足缺一门；
- 其他规则条件不满足；

应单独展示并说明原因。

对应：`REQ-WAIT-005`、`REQ-WAIT-006`

## 22.4 点炮与自摸差异

主结果以当前选择的点炮/自摸模式计算。

若另一模式结论不同，可以附加提示，例如：

```text
五万
点炮：不能胡
自摸：8番
```

两种结果不得混在同一个正式合计中。

对应：`REQ-WAIT-007`

## 22.5 上下文不足

门风、圈风等信息不足时：

- 区分“确定合法听牌”和“待确认听牌”；
- 默认排序和听口统计只使用确定合法听牌。

对应：`REQ-WAIT-008`

---

# 23. 弃牌后听牌分析

完整牌面未和时：

1. 枚举当前可弃牌；
2. 判断弃掉哪张后进入听牌；
3. 对这些可弃牌，在原手牌上方显示小三角；
4. 用户点击某个候选牌；
5. 展示该弃牌后的待胡牌和最高合法结果。

不展示：

- 剩余牌数量；
- 桌面已知牌修正；
- 摸牌概率；
- 绝对胜率。

对应：`REQ-WAIT-001`～`REQ-WAIT-004`

# 24. 听牌排序

设置中提供：

### 默认

```text
高番优先
```

优先排列最高合法结果更高的弃牌/听牌方案。

### 可选

```text
听口优先
```

按不同合法待胡牌种类数排序。

相同情况下使用稳定牌序，避免列表不断跳动。

排序设置：

- 不放在计算主页面；
- 本地记忆。

对应：`REQ-WAIT-003`

听牌/弃牌分析：

允许：

- 查看；
- 复制文字；
- 分享链接。

禁止：

- 保存为“已保存牌例”。

输出必须标记：

```text
听牌分析
```

# 38. 主题与视觉

## 38.1 总体风格

目标：

```text
约 70% 现代工具清晰度
+
约 30% 轻像素风
```

像素元素适合：

- 图标；
- 标签；
- 三角提示；
- 规则卡；
- 小装饰。

复杂规则正文和设置保持现代高可读性。

对应：`REQ-UI-001`

## 38.2 麻将牌

麻将牌清晰度优先于像素风统一。

要求：

- 只显示牌图；
- 不在每张牌上额外堆叠文字；
- 小屏可辨；
- 必要时使用轻像素化而不是过度低分辨率风格。

对应：`REQ-UI-002`

## 38.3 深色模式

不得简单采用纯黑背景。

应保持：

- 舒适；
- 不过暗；
- 牌面高辨识度；
- 长时间观看不刺眼。

对应：`REQ-UI-004`

## 38.4 动画

动画用于状态反馈而非装饰炫技。

禁止：

- 持续闪烁；
- 大范围频繁移动；
- 对“减少动态效果”设置无效。

对应：`REQ-UI-005`

- 计算；
- 复制；
- 分享；
- 导出单牌例。

暂停：

- 保存牌例；
- 草稿恢复；
- 数据导入。

对应：`REQ-STORAGE-003`

## 40.2 多标签页

允许多标签页查看。

同时只允许一个主要 Calculator 编辑器。

其他标签页尝试编辑：

- 提示已有主编辑窗口；
- 可以选择接管；
- 原窗口转只读；
- 异常关闭后锁可释放。

# 41. 规则与应用更新

## 41.1 更新检查

联网时每天最多自动检查一次版本元数据。

不上传：

- 牌面；
- 牌例；
- 设置；
- 设备唯一标识。

允许：

- 手动检查；
- 关闭自动检查。

对应：`REQ-UPDATE-002`

## 41.2 应用更新

发现新版本：

- 立即更新；
- 稍后；
- 查看更新内容。

更新前保存草稿。

旧牌例不因应用升级自动重算。

对应：`REQ-UPDATE-001`

## 41.3 规则更新

规则包只有在：

- 完整下载；
- 格式校验通过；
- 版本校验通过；
- 完整性校验通过；

之后才能启用。

失败：

- 继续使用旧规则；
- 不进入半更新状态；
- 可重试。

对应：`REQ-UPDATE-003`

## 41.4 规则升级

用户可查看规则变更后主动升级。

旧牌例继续引用旧版本。

对应：`REQ-UPDATE-004`

## 47.1 正式版阻断项

存在以下任一项不得正式发布：

- 已知严重错算；
- 已知漏算；
- 和牌合法性严重误判；
- 规则标准测试未通过；
- Save、Restore、Import、Share、Migration 任一链路未实际执行验收；
- Save、Restore、Import、Share、Migration 任一链路未形成明确的 `PASS` 记录；
- Save、Restore、Import、Share、Migration 任一链路结果为 `FAIL` 或结果不明确；
- 手机核心流程失败；
- 桌面核心流程失败；
- 微信浏览器核心流程失败；
- 牌例严重丢失；
- 应用卡死或无法完成主要计算。

正式发布前必须分别实际执行并记录以下五条关键链路：

```text
Save
Restore
Import
Share
Migration
```

五条链路必须各自形成明确的 `PASS` 记录。“没有已知严重故障”不能替代正向验收；任一链路未执行、`FAIL` 或结果不明确，均阻断正式发布。

轻微 UI 问题可以记录后发布。

# 50. 主要空状态与错误文案语义

具体文字可在 UI 设计阶段微调，但语义不可改变。

| 场景 | 必须表达的含义 |
|---|---|
| 结构牌数不足 | 当前还不能开始完整分析 |
| 结构已和但不合法 | 牌型结构成立，但按当前规则不能胡，并说明原因 |
| 没有一步进入听牌 | 当前尚未听牌 |
| 缺少门风/圈风等 | 当前结果尚不能确定，需要补充条件 |
| 待修正状态 | 当前数据存在错误，需修正后才能正式计算 |
| 分析异常 | 本次计算失败，系统没有输出猜测结果 |
| 本地存储失败 | 当前可以临时计算，但数据无法可靠保存 |
| 分享数据损坏 | 数据未通过校验，没有替换当前草稿 |
| 高版本关键不兼容 | 可以预览有限信息，但不能冒险重新计算 |
| 规则更新失败 | 继续使用原规则版本 |
